## LLMBatchGateway API and CRD

- API group/version is `batch.llm-d.ai/v1alpha1`; the CRD is namespaced. [API registration](https://github.com/opendatahub-io/llm-d-batch-gateway-operator/blob/93f1c2c021a7ebae6f44c9e1dd05d7c9a34a46e8/api/v1alpha1/groupversion_info.go#L1-L15), [CRD identity/scope](https://github.com/opendatahub-io/llm-d-batch-gateway-operator/blob/93f1c2c021a7ebae6f44c9e1dd05d7c9a34a46e8/config/crd/bases/batch.llm-d.ai_llmbatchgateways.yaml#L8-L38).
- Required `spec` fields: `secretRef`, `fileStorage`, `apiServer`, `processor`, and `gc`; `processor.asyncConfig` is required. `fileStorage` must contain exactly one of `s3` or `fs`; async config must contain exactly one of `redis` or `sql`. [API markers](https://github.com/opendatahub-io/llm-d-batch-gateway-operator/blob/93f1c2c021a7ebae6f44c9e1dd05d7c9a34a46e8/api/v1alpha1/llmbatchgateway_types.go#L41-L127), [async markers/types](https://github.com/opendatahub-io/llm-d-batch-gateway-operator/blob/93f1c2c021a7ebae6f44c9e1dd05d7c9a34a46e8/api/v1alpha1/llmdasync_types.go#L9-L56), [generated required fields/CEL](https://github.com/opendatahub-io/llm-d-batch-gateway-operator/blob/93f1c2c021a7ebae6f44c9e1dd05d7c9a34a46e8/config/crd/bases/batch.llm-d.ai_llmbatchgateways.yaml#L1318-L1323).
- Schema defaults include `dbBackend: postgresql`, component replicas `1`, and GC interval `30m`; async defaults include concurrency `8`, drain timeout `2m`, Redis poll interval `1000ms`, and batch size `10`. `resultPollTimeout` is controller-required but has no default. SQL `maxConnections` is not schema-defaulted; the chart uses 8 when omitted. [API types](https://github.com/opendatahub-io/llm-d-batch-gateway-operator/blob/93f1c2c021a7ebae6f44c9e1dd05d7c9a34a46e8/api/v1alpha1/llmbatchgateway_types.go#L61-L67), [async types](https://github.com/opendatahub-io/llm-d-batch-gateway-operator/blob/93f1c2c021a7ebae6f44c9e1dd05d7c9a34a46e8/api/v1alpha1/llmdasync_types.go#L15-L49), [SQL fields](https://github.com/opendatahub-io/llm-d-batch-gateway-operator/blob/93f1c2c021a7ebae6f44c9e1dd05d7c9a34a46e8/api/v1alpha1/llmdasync_types.go#L117-L153).
- Semantic controller validation requires `resultPollTimeout`, at least one model gateway, nonempty `inferencePoolName`, queue-name pairs together, queue coverage, an inference Gateway URL, and valid gate configuration ([controller validation](https://github.com/opendatahub-io/llm-d-batch-gateway-operator/blob/93f1c2c021a7ebae6f44c9e1dd05d7c9a34a46e8/internal/controller/llmbatchgateway_controller.go#L718-L825)). Schema-level failures are rejected by Kubernetes admission. Semantic failures on an accepted CR set conditions False with reason `ValidationFailed`, emit a Warning event, and patch status ([failure recording](https://github.com/opendatahub-io/llm-d-batch-gateway-operator/blob/93f1c2c021a7ebae6f44c9e1dd05d7c9a34a46e8/internal/controller/llmbatchgateway_controller.go#L283-L317)).
- The operator's API comment/generated condition description lists Ready plus API, processor, and GC conditions, while controller code also maintains `AsyncProcessorAvailable`. The controller computes Ready as the conjunction of all four component availability conditions ([status code](https://github.com/opendatahub-io/llm-d-batch-gateway-operator/blob/93f1c2c021a7ebae6f44c9e1dd05d7c9a34a46e8/internal/controller/llmbatchgateway_controller.go#L398-L457)).
- TLS supports an existing Secret or cert-manager issuer configuration; those options are mutually exclusive. `httpRoute` can enable a route with parentRefs. [API types](https://github.com/opendatahub-io/llm-d-batch-gateway-operator/blob/93f1c2c021a7ebae6f44c9e1dd05d7c9a34a46e8/api/v1alpha1/llmbatchgateway_types.go#L601-L665).

- Reconcile order: fetch CR → validate → resolve Secret → render Batch Gateway and async charts → add controller owner references → server-side apply → delete stale owned resources → update status → timed requeue. [Controller lines 176-272](https://github.com/opendatahub-io/llm-d-batch-gateway-operator/blob/93f1c2c021a7ebae6f44c9e1dd05d7c9a34a46e8/internal/controller/llmbatchgateway_controller.go#L176-L272).
- The renderer runs Helm templates in-process and decodes the rendered YAML to objects ([renderer lines 52-95](https://github.com/opendatahub-io/llm-d-batch-gateway-operator/blob/93f1c2c021a7ebae6f44c9e1dd05d7c9a34a46e8/internal/controller/helm.go#L52-L95)). It does not create a Helm release.
- Operator reconcile tests observe three Deployments (API server, GC, async processor), one processor StatefulSet, two Services, ConfigMaps, and ServiceAccounts ([test lines 897-1001](https://github.com/opendatahub-io/llm-d-batch-gateway-operator/blob/93f1c2c021a7ebae6f44c9e1dd05d7c9a34a46e8/internal/controller/llmbatchgateway_controller_test.go#L897-L1001)). HTTPRoute and Certificate are optional managed GVKs; stale owned resources are deleted during later reconciles ([managed GVKs and orphan cleanup](https://github.com/opendatahub-io/llm-d-batch-gateway-operator/blob/93f1c2c021a7ebae6f44c9e1dd05d7c9a34a46e8/internal/controller/llmbatchgateway_controller.go#L88-L103), [HTTPRoute template](https://github.com/opendatahub-io/batch-gateway/blob/0947400279d3dbdf892497c8435c4242c0386bf8/charts/batch-gateway/templates/apiserver-httproute.yaml#L1-L46), [Certificate template](https://github.com/opendatahub-io/batch-gateway/blob/0947400279d3dbdf892497c8435c4242c0386bf8/charts/batch-gateway/templates/apiserver-certificate.yaml#L1-L16)).
- Cross-namespace Secret references require ReferenceGrant and are copied into the CR namespace as owned Secrets; same-namespace secrets are referenced directly ([secret sync](https://github.com/opendatahub-io/llm-d-batch-gateway-operator/blob/93f1c2c021a7ebae6f44c9e1dd05d7c9a34a46e8/internal/controller/secret_sync.go#L26-L55), [copy ownership](https://github.com/opendatahub-io/llm-d-batch-gateway-operator/blob/93f1c2c021a7ebae6f44c9e1dd05d7c9a34a46e8/internal/controller/secret_sync.go#L159-L193)).

## Batch API, worker, and storage evidence

- Routes implemented by the API server: `POST/GET /v1/batches`, `GET /v1/batches/{id}`, `POST /v1/batches/{id}/cancel`; file APIs include upload, metadata, content download, list, delete. [Batch routes](https://github.com/opendatahub-io/batch-gateway/blob/0947400279d3dbdf892497c8435c4242c0386bf8/internal/apiserver/batch/batch_handler.go#L65-L91), [file routes](https://github.com/opendatahub-io/batch-gateway/blob/0947400279d3dbdf892497c8435c4242c0386bf8/internal/apiserver/file/file_handler.go#L68-L100).
- Create Batch accepts `input_file_id`, `endpoint`, `completion_window`; input JSONL lines use `custom_id`, `method`, `url`, `body`. Handler checks tenant-scoped file metadata and `purpose=batch`; preprocessor requires POST, relative/allowed path matching the batch endpoint, model ID, and no streaming. [Batch request types/validation](https://github.com/opendatahub-io/batch-gateway/blob/0947400279d3dbdf892497c8435c4242c0386bf8/internal/shared/openai/batch.go#L332-L410), [JSONL request type](https://github.com/opendatahub-io/batch-gateway/blob/0947400279d3dbdf892497c8435c4242c0386bf8/internal/shared/types/job.go#L71-L77), [line validation](https://github.com/opendatahub-io/batch-gateway/blob/0947400279d3dbdf892497c8435c4242c0386bf8/internal/processor/worker/preprocessor.go#L286-L320).
- File bytes use S3 or filesystem; file metadata and batch jobs are PostgreSQL-backed. Upload stores the blob before metadata and removes it if metadata persistence fails ([upload](https://github.com/opendatahub-io/batch-gateway/blob/0947400279d3dbdf892497c8435c4242c0386bf8/internal/apiserver/file/file_handler.go#L201-L262), [storage and metadata write](https://github.com/opendatahub-io/batch-gateway/blob/0947400279d3dbdf892497c8435c4242c0386bf8/internal/apiserver/file/file_handler.go#L342-L353)). PostgreSQL `batch_items` is the core job queue and uses atomic `FOR UPDATE SKIP LOCKED` claims ([schema](https://github.com/opendatahub-io/batch-gateway/blob/0947400279d3dbdf892497c8435c4242c0386bf8/internal/database/postgresql/batch_schema.sql#L14-L70), [queue claim](https://github.com/opendatahub-io/batch-gateway/blob/0947400279d3dbdf892497c8435c4242c0386bf8/internal/database/postgresql/batch_queue.go#L114-L145)).
- The API server records configured pass-through header values in batch tags before persisting the job ([batch handler](https://github.com/opendatahub-io/batch-gateway/blob/0947400279d3dbdf892497c8435c4242c0386bf8/internal/apiserver/batch/batch_handler.go#L193-L218)); the worker later passes these values into request planning ([worker](https://github.com/opendatahub-io/batch-gateway/blob/0947400279d3dbdf892497c8435c4242c0386bf8/internal/processor/worker/execute_pipeline.go#L120-L133)). The code captures a value at batch creation and does not refresh it during processing. This makes token storage/retention and token lifetime an explicit security review item.
- GC runs immediately on startup and then on its configured interval; it removes expired jobs and physical file objects before metadata ([collector](https://github.com/opendatahub-io/batch-gateway/blob/0947400279d3dbdf892497c8435c4242c0386bf8/internal/gc/collector/collector.go#L174-L223), [delete behavior](https://github.com/opendatahub-io/batch-gateway/blob/0947400279d3dbdf892497c8435c4242c0386bf8/internal/gc/collector/collector.go#L225-L296)).

## Redis and SQL async queue distinction

- Redis/Valkey is the Red Hat 3.5 documented queue path; Red Hat documentation says PostgreSQL metadata, Redis/Valkey queue, and S3-compatible input/output storage. [Batch inference on OpenShift guide](https://docs.redhat.com/en/documentation/red_hat_ai_inference/3.5/html/batch_process_inference_requests_with_distributed_inference_with_llm-d/batch-inference-with-llmd_batch-processing-inference-requests#llmd-configuring-batch-inference-on-ocp_batch-processing-inference-requests).
- The 3.6-pinned operator schema requires one of `asyncConfig.redis` or `asyncConfig.sql`; neither transport is an implicit API default. The product fork documents Redis/Valkey sorted-set as recommended and SQL as experimental ([pinned chart README](https://github.com/opendatahub-io/batch-gateway/blob/0947400279d3dbdf892497c8435c4242c0386bf8/charts/batch-gateway/README.md#L126-L188), [pinned async transport README](https://github.com/opendatahub-io/llm-d-async/blob/140885437eeb7fe0d0d59e6cc7bf1f548e9aaa09/README.md#L64-L72)).
- Redis uses `redis-url`; SQL uses the shared PostgreSQL URL and creates async tables. SQL result reads are destructive and do not provide Redis-style result acknowledgement; restart can cause unresolved requests to be resubmitted and inference to run again ([operator-pinned chart README](https://github.com/opendatahub-io/batch-gateway/blob/0947400279d3dbdf892497c8435c4242c0386bf8/charts/batch-gateway/README.md#L147-L188), [async SQL transport docs](https://github.com/opendatahub-io/llm-d-async/blob/140885437eeb7fe0d0d59e6cc7bf1f548e9aaa09/docs/transports.md#L301-L305)).
- The operator maps Redis to `redis-sortedset` and `redis-url`, SQL to `sql` and `postgresql-url` in the async chart ([mapper](https://github.com/opendatahub-io/llm-d-batch-gateway-operator/blob/93f1c2c021a7ebae6f44c9e1dd05d7c9a34a46e8/internal/controller/helm_async.go#L83-L130)). The sample uses Redis for the main walkthrough; SQL is described as experimental and requires confirmation that promoted 3.6 images contain compatible SQL producer support ([handoff lines 88-94](https://github.com/aneeshkp/rhaii-docs/blob/d38076730c2331d85375b4fef26348d4e17fd12e/docs/batch-inference-installation-handoff.md#L88-L94)).

4. No cluster version, hardware, `LLMBatchGateway` status, resource output, or live batch result was supplied. The cluster table uses placeholders and the article provides commands rather than invented output.
5. The HTTPRoute, TLS Certificate, and auth-policy behavior depend on the installed Gateway API/cert-manager/policy stack. The Batch Gateway operator creates only the objects configured by its CR; the cluster Gateway, listener, DNS, external auth policy, and backend TLS behavior remain platform configuration.

## Model-routing boundary for diagrams

- The 3.6 handoff states the Batch Gateway Operator does not create the internal ClusterIP Gateway or per-model HTTPRoutes; the installation prepares them separately. Its model route sends traffic to an `InferencePool`, and its `InferenceObjective` supplies the batch priority ([handoff namespace/Gateway/objective/route sections](https://github.com/aneeshkp/rhaii-docs/blob/d38076730c2331d85375b4fef26348d4e17fd12e/docs/batch-inference-installation-handoff.md#L602-L755)).
- The operator-managed `spec.httpRoute` is a separate route for the external Batch API (`/v1/batches` and `/v1/files`), not the model route ([operator API](https://github.com/opendatahub-io/llm-d-batch-gateway-operator/blob/93f1c2c021a7ebae6f44c9e1dd05d7c9a34a46e8/api/v1alpha1/llmbatchgateway_types.go#L637-L665), [chart template](https://github.com/opendatahub-io/batch-gateway/blob/0947400279d3dbdf892497c8435c4242c0386bf8/charts/batch-gateway/templates/apiserver-httproute.yaml#L31-L46)).
- The pinned async processor uses a request's endpoint when present, overriding the queue's fallback `requestPathURL`; therefore the configured inference-gateway base URL must include the namespace/model prefix matched by the internal route ([pinned async source](https://github.com/opendatahub-io/llm-d-async/blob/140885437eeb7fe0d0d59e6cc7bf1f548e9aaa09/pkg/async/mergepolicy/randomrobin/random_robin_policy.go#L177-L185)).
- The flow-control objective is transmitted on each inference request as `x-gateway-inference-objective` ([pinned async source](https://github.com/opendatahub-io/llm-d-async/blob/140885437eeb7fe0d0d59e6cc7bf1f548e9aaa09/pkg/async/mergepolicy/randomrobin/random_robin_policy.go#L188-L194)).
